# ai-advice

Мультиагентная ИИ-система персонального консультирования на базе [Kilo Code](https://kilocode.ai). Помогает решать широкий спектр жизненных и профессиональных задач — от бытовых вопросов до юридических, медицинских, финансовых, технических, творческих и организационных.

## Архитектура

Система построена по принципу «оркестратор + специализированные субагенты». Все агенты живут в `.kilo/agent/` и загружаются Kilo Code автоматически из конфигурации проекта — глобальный `kilo.jsonc` не требуется.

```
.kilo/
  ├── agent/
  │   ├── advice.md    — Советник (primary agent)
  │   ├── law.md       — Лекс, юридический агент (subagent)
  │   ├── medical.md   — Медик, медицинский агент (subagent)
  │   └── produce.md   — Ридли, продюсерский агент (subagent)
  └── skills/
      └── artist/
          └── SKILL.md — Маэстро, художественная экспертиза (skill)
```

**Советник** (`advice.md`) — универсальный оркестратор. Принимает запрос пользователя, классифицирует его по доменам, при необходимости привлекает специализированных субагентов через механизм `task`, синтезирует информацию из нескольких источников и выдаёт структурированный ответ с конкретным планом действий.

## Субагенты

| Агент | Файл | Домен | Примеры задач |
|-------|------|-------|---------------|
| **Лекс** | `.kilo/agent/law.md` | Право | Анализ договоров, составление исков, правовые консультации, комплаенс, сравнительно-правовой анализ. Приоритетная экспертиза — законодательство РФ |
| **Медик** | `.kilo/agent/medical.md` | Медицина | Дифференциальная диагностика, рекомендации по лечению и обследованию, проверка доступности препаратов на рынке РФ, экстренные состояния |
| **Ридли** | `.kilo/agent/produce.md` | Продакшн | Кинопроизводство, музыка, подкасты, ивенты, цифровой контент. Бюджетирование, календарное планирование, кастинг, дистрибуция, питчинг |

Субагенты работают автономно: получают полный контекст задачи, проводят собственное исследование (включая веб-поиск через инструменты оркестратора — SearXNG/webfetch), и возвращают готовый результат оркестратору для финального синтеза. Каждый субагент имеет чёткие границы компетенции и при необходимости рекомендует обратиться к смежному агенту.

## Скиллы

Скиллы — альтернативный механизм расширения возможностей Советника. В отличие от субагентов (которые работают автономно на выделенной модели), скилл загружает экспертизу в контекст самого Советника, и тот выполняет задачу своими инструментами.

### Маэстро — художественная экспертиза

| | |
|---|---|
| **Файл** | `.kilo/skills/artist/SKILL.md` |
| **Домен** | Визуальное искусство: рисунок, фотография, дизайн, иллюстрация |
| **Механизм** | Skill (загружается в контекст Советника) |

Скилл даёт Советнику компетенции для:
- **Анализа изображений** — определение стиля, техники, композиции, цветовой палитры, освещения
- **Создания изображений** — генерация рисунков, художественных фото, иллюстраций, дизайн-макетов
- **Редактирования** — стилизация, цветокоррекция, добавление/удаление объектов

**Почему skill, а не subagent:** модели для генерации изображений не поддерживают tool use — они не могут вызывать инструменты (`read`, `write`, `bash`). Поэтому Советник не делегирует им задачу, а загружает художественную экспертизу через skill и сам вызывает image-модель через API.

**Настройка:**

1. Создайте файл `.kilo/artist-model.json` (добавлен в `.gitignore` — не коммитится):
   ```json
   {
     "image_model": "<model-slug>",
     "provider_url": "<api-base-url>",
     "api_key": "<your-api-key>"
   }
   ```
2. Советник автоматически прочитает этот файл при загрузке скилла и использует указанную модель и ключ для API-вызовов.

**Использование:** просто попросите Советника проанализировать изображение или создать новое — «нарисуй дракона в стиле киберпанк», «разбери эту фотографию по композиции», «сгенерируй обложку для книги». Советник сам загрузит скилл, прочитает конфиг и выполнит задачу.

## Возможности Советника

- **Автоматическая классификация** запроса по домену (право, медицина, финансы, техника, кулинария, быт, путешествия)
- **Параллельная обработка** — при смешанных вопросах запускает несколько субагентов одновременно (например: `law + medical` при ДТП)
- **Веб-исследование** — поиск через self-hosted SearXNG MCP (веб-поиск по движкам Google/Bing/Яндекс/Brave, извлечение страниц, проверка доступности инстанса) с автоматическим fallback'ом на прямую загрузку страниц при недоступности SearXNG
- **Обход блокировок** — при недоступности страницы через SearXNG или прямую загрузку использует Playwright (JavaScript-рендеринг, обход Cloudflare)
- **Точные расчёты** — все финансовые, налоговые и прочие вычисления выполняются через Python
- **Адаптивный формат ответа** — от 2–4 предложений для простых вопросов до многостраничного структурированного разбора для сложных межотраслевых ситуаций
- **Работа с изображениями** — художественный анализ (стиль, композиция, цвет, свет) и генерация изображений через API (рисунки, фото, иллюстрации, дизайн). Советник загружает скилл `artist` и вызывает image-модель напрямую
- **Структурированное рассуждение** — Sequential Thinking MCP позволяет Советнику вести пошаговый анализ с проверкой гипотез, возвратом к предыдущим шагам и ветвлением логики (особенно полезно для юридических, медицинских и финансовых кейсов)

## Контекст пользователя

Персональные данные пользователя вынесены в отдельный файл `user_context.md` (в корне проекта) и загружаются автоматически через механизм `instructions` конфигурации Kilo Code. Файл добавлен в `.gitignore` — каждый пользователь создаёт свой локальный `user_context.md` на основе шаблона `user_context.example.md`.

```markdown
# user_context.md (пример)
- Имя: Дмитрий
- Дата рождения: 14.11.1992
- Место проживания: Россия, Санкт-Петербург
- Языки: русский (родной), английский (C1)
```

Системный промпт Советника не содержит жёстко зашитых персональных данных — контекст пользователя подгружается динамически.

## MCP-серверы

Советник использует два MCP-сервера, расширяющих его исследовательские и аналитические возможности. Подключение настраивается в конфигурации Kilo Code (`~/.config/kilo/kilo.jsonc`, секция `mcp`).

### SearXNG Search

Веб-поиск и извлечение контента через self-hosted инстанс SearXNG — метапоисковик, агрегирующий 70+ поисковых движков (Google, Bing, Яндекс, Brave и др.). Полностью бесплатно, без API-ключей, работает в РФ.

**Доступные инструменты:**

| Инструмент | Назначение |
|---|---|
| `searxng_searxng_web_search` | Веб-поиск по запросу (заголовки, сниппеты, ссылки); фильтры по языку, движкам, категориям, времени |
| `searxng_web_url_read` | Извлечение содержимого с конкретного URL (Markdown, секции по заголовку, PDF) |
| `searxng_searxng_instance_info` | Проверка доступности инстанса и его возможностей (категории, движки, локали) |
| `searxng_searxng_search_suggestions` | Автодополнение поискового запроса |

**Установка (вариант «всё под WSL2»):** Docker и Node.js живут внутри дистрибутива WSL2 (Ubuntu), на хост-систему ставить ничего не нужно.

1. Создай `~/.searxng/settings.yml` внутри WSL2 (JSON-формат выдачи обязателен для MCP-сервера):

```yaml
use_default_settings: true

search:
  formats:
    - html
    - json    # обязательно для MCP-сервера, без этого результаты не отдадутся

server:
  secret_key: "сгенерируй-случайную-строку"  # например: openssl rand -hex 32
  limiter: false

outgoing:
  request_timeout: 10.0
```

2. Запусти контейнер:

```bash
docker run -d \
  --name searxng \
  --restart unless-stopped \
  -p 8888:8080 \
  -v ~/.searxng/settings.yml:/etc/searxng/settings.yml:rw \
  searxng/searxng:latest
```

3. (Опционально) Приоритизация движков для РФ. В `settings.yml` добавь секцию `engines:` с весами — иначе в общей выдаче может доминировать `google cse`, а Яндекс и Bing проигрывать по рейтингу:

```yaml
engines:
  - name: yandex
    disabled: false
    weight: 2.0   # поднимает результаты Яндекса в общей выдаче
    timeout: 8.0  # Яндекс может отвечать медленно
  - name: bing
    disabled: false
    weight: 1.5
    timeout: 6.0
  - name: google cse
    disabled: false
    weight: 1.0   # можно понизить, чтобы не доминировал
```

После правок конфига — `docker restart searxng`.

4. Конфигурация Kilo (`kilo.jsonc`):

```jsonc
"searxng": {
  "type": "local",
  "command": ["wsl", "bash", "-c", "export SEARXNG_URL=http://localhost:8888 && npx -y mcp-searxng"],
  "enabled": true
}
```

Нюансы:
- Дистрибутив WSL не по умолчанию — добавь `-d <имя>` после `wsl` (список: `wsl --list`).
- `localhost` из Windows не работает — подставь IP дистрибутива (`wsl hostname -I`) в `SEARXNG_URL`.
- На нативной Linux-машине (без WSL2) команда проще:

```jsonc
"searxng": {
  "type": "local",
  "command": ["npx", "-y", "mcp-searxng"],
  "env": {
    "SEARXNG_URL": "http://localhost:8888"
  },
  "enabled": true
}
```

**Диагностика при проблемах:**

| Проблема | Проверить |
|---|---|
| Инстанс не отвечает | `wsl docker ps -a` — контейнер в статусе Up, порт 8888 проброшен |
| Ошибка `Invalid settings.yml` | `wsl docker logs searxng` — невалидный конфиг; `secret_key` должен быть строкой |
| Поиск падает с таймаутом после перезапуска | Дай контейнеру 10–15 секунд после `docker restart` |
| В выдаче только один движок | Ранжирование по score; настрой `weight` движков (см. п. 3) |
| Движки ловят CAPTCHA/лимиты | google/duckduckgo/startpage — ожидаемо в РФ; полагайся на yandex/bing/brave/mojeek |
| `npx` не может скачать пакет | Доступ к npm registry: `curl -s https://registry.npmjs.org/` в WSL2 |

> **Примечание:** Советник спроектирован с расчётом на возможную недоступность SearXNG (отключён в конфиге, контейнер упал, таймаут). При недоступности он автоматически переключается на fallback-стратегию: `webfetch` + собственные знания об авторитетных источниках, а при JS-сайтах — Playwright. Система остаётся работоспособной и без SearXNG — просто с меньшей глубиной поиска.

### Sequential Thinking

Обеспечивает структурированное многошаговое рассуждение с возможностью пересмотра предыдущих шагов, ветвления логики и проверки гипотез.

**Установка (WSL2 на Windows):**

Node.js устанавливается внутрь WSL2 (Ubuntu), на хост-систему — ничего:

```bash
# В WSL2:
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
sudo apt-get install -y nodejs
```

**Конфигурация Kilo (`kilo.jsonc`):**

```jsonc
"sequential-thinking": {
  "type": "local",
  "command": ["wsl", "bash", "-c", "npx -y @modelcontextprotocol/server-sequential-thinking"],
  "enabled": true
}
```

На нативной Linux-машине (без WSL2) команда проще:

```jsonc
"sequential-thinking": {
  "type": "local",
  "command": ["npx", "-y", "@modelcontextprotocol/server-sequential-thinking"],
  "enabled": true
}
```

**Диагностика при проблемах:**

| Проблема | Проверить |
|---|---|
| Kilo показывает ошибку подключения | `wsl bash -c "npx -y @modelcontextprotocol/server-sequential-thinking"` в PowerShell — запускается ли вручную? |
| `npx` не может скачать пакет | Доступ к npm registry: `curl -s https://registry.npmjs.org/` в WSL2 |
| Node.js не установлен в WSL2 | `wsl bash -c "node --version"` |
| WSL2 не установлен | `wsl --status` в PowerShell. Если нет — [инструкция по установке](https://learn.microsoft.com/ru-ru/windows/wsl/install) |

После изменения конфигурации Kilo требуется перезапуск (`/exit` и открыть заново). MCP-серверы подхватываются автоматически — `npx` скачает пакеты при первом запуске и закеширует.

## Установка и использование

1. Установите [Kilo Code](https://kilocode.ai) в VS Code
2. Клонируйте репозиторий:
   ```bash
   git clone git@github.com:Chirontex/ai-advice.git
   ```
3. Создайте `user_context.md` на основе `user_context.example.md` и заполните своими данными
4. Настройте MCP-серверы в глобальной конфигурации Kilo (`~/.config/kilo/kilo.jsonc`) — секции `mcp.searxng` и `mcp.sequential-thinking` (см. раздел выше)
5. Откройте проект в Kilo Code — агенты загрузятся автоматически из `.kilo/agent/`

**Никакой ручной настройки промптов агентов не требуется** — всё уже в репозитории. MCP-серверы и модель настраиваются один раз в глобальной конфигурации.

## Сторонние источники данных

Субагенты используют следующие внешние источники для получения актуальных данных (помимо веб-поиска через MCP-серверы Советника):

- **Юриспруденция:** GitHub-репозитории с MCP-серверами российского права, правовые базы
- **Медицина:** Клинические рекомендации МЗ РФ, PubMed, Cochrane, Vidal.ru, RLS.ru, ГРЛС (Государственный реестр лекарственных средств)
- **Продакшн:** Фестивальные платформы, грантовые порталы (Президентский фонд культурных инициатив, Фонд кино и др.), стриминговые сервисы
