# Infographic Skill: инфографика, слайды, постеры

## Зачем этот скилл

В прошлых сессиях инфографика делалась «на глаз» и многократно ломалась:
текст вылезал за поля, контент не влезал в экран, точки прогресса не
обновлялись, а проверять глазами модель не могла. Этот навык фиксирует
**рабочий процесс и проверенные шаблоны**, чтобы инфографика получалась
правильной с первой попытки: вёрстка, которая не может переполниться,
и автоматическая верификация без визуального осмотра.

## Ключевой принцип (самый важный урок)

**Никогда не верстай текст абсолютными координатами «на глаз» — ни в SVG,
ни в HTML.** Вместо этого:

1. **HTML + CSS с автопотоком контента** (flex/grid, обычные блочные
   элементы): текст сам переносится, карточки растягиваются под
   содержимое, переполнение исключено по построению.
2. **Верификация через Playwright** (`getBoundingClientRect` по каждому
   элементу): проверяй фактические границы, а не предполагаемые.
   Модель может не видеть рендер глазами — но геометрию измеряет точно.

SVG допустим только для простых статичных диаграмм без текста или с
жёстко фиксированными короткими подписями. Текст + SVG = боль.

## Триггер использования

- Запрос про **инфографику, слайды, постеры, мобильные пейджеры, визуалы**:
  «сделай инфографику», «переверстай под смартфон», «рендерь в PNG».
- Данные + задача оформить наглядно (таблица цифр → слайд).
- Доработка существующей инфографики: цвет, вёрстка, адаптивность.

## Окружение и инструменты

- **HTML/CSS** + минимум JS (пейджер, свайп) — основной материал.
- **Playwright + локальный Edge** (`p.chromium.launch(channel="msedge")`)
  — рендер и верификация. Без скачивания Chromium.
- **Python + Pillow** — только если нужен точный замер шрифтов
  (редко; при HTML-вёрстке не требуется).
- Windows + PowerShell: **heredoc `<<` в PowerShell не работает** — пиши
  python-скрипты файлом через `write`, затем `python file.py`.
- Кириллица в stdout: `$env:PYTHONIOENCODING="utf-8"` перед запуском.
- Файлы клади в `develop/<тема>/`, имя файла = имя папки (правила
  Working Directory из основной инструкции).

## Алгоритм работы

### 1. Собрать контент

Перед вёрсткой сформулируй **точное содержание** слайдов: цифры, тексты,
подписи. Не «сделай красиво», а «слайд 1: 3 KPI, таблица потолков,
вывод; слайд 2: 7 коридоров…».

### 2. Выбрать формат по аудитории

| Формат | Когда |
|---|---|
| Мобильный пейджер (рекомендуется) | просмотр на телефоне: один слайд = один экран, свайп |
| Веб-слайды 1200×900 + PNG | десктоп, вставка в документы, пересылка |
| Лонгрид | много текста, вертикальный скролл допустим |

Мобильный пейджер: каждый `.slide` занимает ровно `100dvh` экрана,
**без прокрутки внутри слайда**; скролл страницы отключён
(`html,body{overflow:hidden}`), переключение только JS.

### 3. Вёрстка (правила, выработанные практикой)

**Структура слайда (мобильный пейджер):**
```
<section class="slide active" id="s1">   <!-- ровно один active -->
  <шапка: орнамент/номер/заголовок/подзаголовок>
  <div class="body">  <!-- flex column, justify-content:center -->
    ...карточки...
  </div>
</section>
```

**Критичные правила:**
- `.body { display:flex; flex-direction:column; justify-content:center; gap:10px }`
  — контент **отцентрован по вертикали** (не прижимать к верху).
- **Никакого `margin-top:auto`** у нижних карточек: при центрировании он
  создаёт пустоту посредине. Прижимать к низу не нужно.
- Вертикальная компоновка: шапка (~100px) + body (flex:1) + таб-бар (60px).
- Компактный режим для низких экранов: `@media (max-height:700px)` —
  ужимать шрифты/отступы, чтобы слайд влезал и на iPhone SE (375×667).
- Карточки с цветной полосой слева (3px) — быстрый визуальный код.
- Проверяй **обе точки**: 390×844 (обычный iPhone) и 375×667 (SE).

**Пейджер (JS):**
- Функция `go(i)` переключает слайд И точки: тут, а не напрямую
  манипуляцией классов.
- **Обязательно экспортируй `window.go = go`** — рендер-скрипт и тесты
  используют её, иначе точки прогресса в PNG не обновляются (живой
  баг из практики: точки были «одинаковые на всех слайдах»).
- Точки прогресса: `.dot` внизу, класс `.on` у активной.
- Свайп: touchstart/touchend по delta X (>50px), клавиатура: стрелки.

### 4. Стилизация

- Тёмная тема + палитра из 3–4 акцентов (не более): красный/фиолетовый/
  сталь, синий/зелёный/фиолетовый — под контекст задачи.
- **Прежде чем выбирать гамму — спроси у пользователя или возьми из
  контекста** (в этом проекте у пользователя готическая группа:
  «кровь и сталь» без коричневого и жёлтого; **не выдумывай чужие
  города и не вставляй случайные надписи** — в практике был баг
  «MOSCOW · SANCTUARY» в петербургской инфографике).
- Готика/сдержанный стиль: орнаментальные надписи, геральдические
  символы `◆ † ◈`, но без клоунады — сначала рабочая информация,
  стиль вторичен.

### 5. Автоматическая верификация (обязательна!)

**Все три проверки запускать ДО сдачи.** Скрипты в `utils/` этого
скилла (параметризованы, принимают путь к HTML):

```powershell
$env:PYTHONIOENCODING="utf-8"
python utils/verify_layout.py path\to\deck.html   # overflow по Y на 390x844 и 375x667
python utils/verify_centering.py path\to\deck.html # отступы сверху=снизу по каждому слайду
python utils/verify_dots.py path\to\deck.html       # активная точка совпадает со слайдом
```

Верифицируй именно класс `.slide`/`.body`, по одному активируя слайды
(скрытые имеют нулевые размеры — общий подводный камень).
Декоративные absolute-элементы (виньетки, розетки, орнаменты) маркируй
`aria-hidden="true"` — верификаторы их игнорируют по соглашению
(в практике был ложный FAIL из-за декора, выходящего за край слайда).

### 6. Рендер в PNG (если нужен)

```powershell
python utils/render_slides.py path\to\deck.html out\dir 390 844
```
Каждый слайд → PNG 2× через `window.go(i)` (не через манипуляцию классов).

### 7. Сдача

Ссылки на файлы + короткое описание каждого слайда. Укажи, что проверено
(overflow=0, центрирование=0, точки=OK) — это уже само по себе снимает
половину итераций.

## Definition of Done (самопроверка)

- [ ] Контент слайдов собран и согласован заранее (числа точные)
- [ ] Вёрстка на HTML/CSS с автопотоком, без абсолютных координат текста
- [ ] Контент отцентрован по вертикали (проверено: отступы сверху = снизу)
- [ ] Каждый слайд влезает в экран без прокрутки (390×844 и 375×667)
- [ ] Активная точка прогресса совпадает со слайдом (verify_dots = OK)
- [ ] Горизонтального переполнения нет (verify_layout = OK)
- [ ] Палитра согласована с контекстом, без случайных надписей
- [ ] PNG-рендер через `window.go()`, а не манипуляцию классов

## Границы

- Не создаёт данные: цифры берутся из проверенных источников/расчётов.
- Не делает анимированную/интерактивную инфографику кроме пейджера
  со свайпом (это не задача скилла).
- Не заменяет дизайнерские решения: стиль по контексту, но содержание
  имеет приоритет над украшательством.
